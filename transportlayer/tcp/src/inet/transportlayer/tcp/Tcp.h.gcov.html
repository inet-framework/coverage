      36                 :             :  * **Communication with clients**
      37                 :             :  *
      38                 :             :  * This section describes the interface between the Tcp module and its clients
      39                 :             :  * (applications or higher-layer protocols). However, note that implementors
      40                 :             :  * of client modules do not necessarily need to know the details described herein.
      41                 :             :  * Instead, they can use the TcpSocket utility class which hides the details
      42                 :             :  * of talking to Tcp under an easy-to-use class interface.
      43                 :             : 
      44                 :             :  * For communication between client applications and TCP, the TcpCommandCode
      45                 :             :  * and TcpStatusInd enums are used as message kinds, and TcpCommand
      46                 :             :  * and its subclasses are used as control info.
      47                 :             :  *
      48                 :             :  * To open a connection from a client app, send a cMessage to TCP with
      49                 :             :  * TCP_C_OPEN_ACTIVE as message kind and a TcpOpenCommand object filled in
      50                 :             :  * and attached to it as control info. (The peer TCP will have to be LISTENing;
      51                 :             :  * the server app can achieve this with a similar cMessage but TCP_C_OPEN_PASSIVE
      52                 :             :  * message kind.) With passive open, there's a possibility to cause the connection
      53                 :             :  * "fork" on an incoming connection, leaving the original connection LISTENing
      54                 :             :  * on the port (see the fork field in TcpOpenCommand). Note that TcpOpenCommand
      55                 :             :  * allows tcpAlgorithmClass to be specified, which will override the setting
      56                 :             :  * in the TCP module. Also note that TcpOpenCommand allows the client to
      57                 :             :  * choose between "autoread" and "explicit-read" modes.
      58                 :             :  *
      59                 :             :  * The client can send data by assigning the TCP_C_SEND message kind to the data
      60                 :             :  * packet and sending it to TCP. Received data will be forwarded by TCP to the
      61                 :             :  * client as messages with the TCP_I_DATA message kind. This happens
      62                 :             :  * automatically in "autoread" mode. In "explicit-read" mode, the client must
      63                 :             :  * issue READ requests to receive data. READ requests are cMessages with the
      64                 :             :  * TCP_C_READ message kind and a TcpReadCommand control info attached.
      65                 :             :  *
      66                 :             :  * To close, the client sends a cMessage to TCP with the TCP_C_CLOSE message kind
      67                 :             :  * and TcpCommand control info.
      68                 :             :  *
      69                 :             :  * Tcp sends notifications to the application whenever there's a significant
      70                 :             :  * change in the state of the connection: established, remote TCP closed,
      71                 :             :  * closed, timed out, connection refused, connection reset, etc. These
      72                 :             :  * notifications are also cMessages with message kind TCP_I_xxx
      73                 :             :  * (TCP_I_ESTABLISHED, etc.) and TcpCommand as control info.
      74                 :             :  *
      75                 :             :  * One TCP module can serve several application modules, and several
      76                 :             :  * connections per application. When talking to applications, a
      77                 :             :  * connection is identified by the socketId that is assigned by the application in
      78                 :             :  * the OPEN call.
      79                 :             :  *
      80                 :             :  * **Sockets**
      81                 :             :  *
      82                 :             :  * The TcpSocket C++ class is provided to simplify managing TCP connections
      83                 :             :  * from applications. TcpSocket handles the job of assembling and sending
      84                 :             :  * command messages (OPEN, CLOSE, etc) to TCP, and it also simplifies
      85                 :             :  * the task of dealing with packets and notification messages coming from Tcp.
      86                 :             :  *
      87                 :             :  *
      88                 :             :  * **Communication with the IP layer**
      89                 :             :  *
      90                 :             :  * The TCP model relies on sending and receiving L3AddressReq/L3AddressInd tags
      91                 :             :  * attached to TCP segment packets.
      92                 :             :  *
      93                 :             :  *
      94                 :             :  * **Architecture**
      95                 :             :  *
      96                 :             :  * This section describes the internal architecture of the TCP model.
      97                 :             :  * The implementation is composed of several classes (discussion follows below):
      98                 :             :  *  - Tcp: the main module class
      99                 :             :  *  - TcpConnection: module class that manages a connection
     100                 :             :  *  - TcpSendQueue, TcpReceiveQueue: send and receive queues
     101                 :             :  *  - TcpAlgorithm: abstract base class for TCP algorithms: DumbTcp, TcpTahoe,
     102                 :             :  *    TcpReno, TcpNewReno, etc.
     103                 :             :  *
     104                 :             :  * Tcp is subclassed from cSimpleModule. It manages socketpair-to-connection
     105                 :             :  * mapping, and dispatches segments and user commands to the appropriate
     106                 :             :  * TcpConnection object.
     107                 :             :  *
     108                 :             :  * TcpConnection manages the connection, with the help of other objects.
     109                 :             :  * TcpConnection itself implements the basic Tcp "machinery": takes care
     110                 :             :  * of the state machine, stores the state variables (TCB), sends/receives
     111                 :             :  * SYN, FIN, RST, ACKs, etc.
     112                 :             :  *
     113                 :             :  * TcpConnection internally relies on 3 objects: send queue, receive queue,
     114                 :             :  * and TCP algorithm. The first two are TcpSendQueue and TcpReceiveQueue.
     115                 :             :  * They manage the actual data stream, so TcpConnection need to only concern
     116                 :             :  * itself with sequence numbers.
     117                 :             : 
     118                 :             :  * The TCP algorithm class is subclassed from TcpAlgorithm. Control over
     119                 :             :  * retransmissions, congestion control and ACK sending are "outsourced"
     120                 :             :  * from TcpConnection into TcpAlgorithm: delayed acks, slow start, fast rexmit,
     121                 :             :  * etc. are all implemented in TcpAlgorithm subclasses. This simplifies the
     122                 :             :  * design of TcpConnection and makes it a lot easier to implement new Tcp
